# Project Summary

I built this project as a student finance database for a university assignment. The goal was to design a relational database that could track incomes, expenses, categories, accounts, and monthly budgets in a way that reflects real financial activity.

## Problem addressed

Students often manage several income sources and recurring expenses at the same time. This project organizes that information in a structured database so it can be validated, summarized, and reviewed over time.

## Main features

- student information management
- income tracking by source and date
- transaction history for different accounts
- spending categories and monthly budgets
- constraints and validation rules
- reporting queries for financial analysis
- PL/SQL logic for recurring finance operations

## Database design

The schema includes tables for students, incomes, categories, bank accounts, transactions, and monthly budgets. The relationships are designed to reflect real financial behavior, such as one student having multiple accounts and multiple transactions across categories.

## What I learned

This project helped me practice database design, normalization, SQL querying, and the use of PL/SQL for business logic. It also showed me how important constraints and triggers are when working with financial data, where incorrect records can affect the whole system.

## Why it is a useful project

It is a practical example of working with a transactional database in a realistic domain. It demonstrates understanding of data relationships, reporting, and backend logic that are relevant for database, analytics, and data-focused roles.
